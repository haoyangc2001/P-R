产业链模式#

模式 做什么 代表
IDM（垂直整合） 设计 + 制造 + 封测全包 Intel、三星

1. 一个关键前提：芯片 = 数字 + 模拟 + 存储宏#

理解芯片设计前，先要明确： 任何一颗芯片，都是「数字电路 + 模拟电路 + 存储/自定义宏」的组合，只是配比不同。

1.1 芯片"种类"与"产品"的区别#

这两个是不同维度，容易混淆：

维度一：电路类型   →  数字电路 / 模拟电路 / 混合信号
维度二：芯片功能   →  CPU / GPU / 存储器 / 射频 / 电源芯片 ...
  • 芯片种类：技术分类（CPU、GPU、存储器……）
  • 芯片产品：具体型号（Apple M4、NVIDIA H100、某厂 DRAM 颗粒……）

产品 = 某公司 + 某型号 + 某工艺节点 + 某套设计实现

1.2 各种芯片的数字/模拟配比#

芯片 主体电路 说明
CPU / GPU 数字为主（~99%） 但必须含模拟：PLL、电源管理、高速接口 PHY
SRAM（缓存） 数字为主 6 管存 1 bit；阵列通常手工设计为宏单元
DRAM（内存） 模拟味重 1 电容存 1 bit；电荷、灵敏放大器、刷新全是模拟问题
Flash / NAND 模拟味更重 浮栅存电荷、阈值电压、多电平
ADC / DAC 纯模拟
射频芯片 纯模拟 收发机、LNA、混频器
电源芯片 纯模拟 LDO、DC-DC

要点：

  • 几乎所有"数字芯片"里都藏着一小撮模拟电路（PLL、电源、接口）
  • 反之，模拟芯片也常配一点数字逻辑（校准、控制）
  • 几乎不存在"纯数字芯片"

1.3 关键：哪些走"我们学的全流程"？#

┌──────────────────────────────────────────────────────────┐
│            RTL → 综合 → 网表 → 布局 → 布线 → GDSII          │
│            ↑                                             │
│      这是【数字电路】的全自动流程                            │
│      前提：RTL 可描述 + 有标准单元库 + 逻辑等价即正确          │
└──────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────┐
│           模拟电路：另一套流程                              │
│  电路图设计 → 手工版图（匹配/对称/屏蔽）→ 反复仿真 → GDSII   │
│  没有 RTL、没有综合、没有自动 P&R，靠经验 + SPICE 仿真         │
└──────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────┐
│           存储阵列：手工设计为【宏单元】                      │
│  在数字 P&R 的 Floorplan 阶段被作为"大块头"摆进去             │
└──────────────────────────────────────────────────────────┘

数字流程的三大前提（模拟都不满足）：

前提 数字 模拟
用 RTL 描述功能 ✅ ❌
有标准单元库 ✅ ❌（每个器件定制）
逻辑等价即正确 ✅ ❌（位置/尺寸影响性能）

结论：我们学的全流程（RTL→综合→P&R→GDSII）是「数字电路」的专属流程。 模拟部分走手工路线，存储阵列做成宏单元被"摆"进去，最后拼在一起。

1.4 典型产品拆解：DRAM / LPDDR（以长鑫存储为例）#

以国产 DRAM 厂商长鑫存储（CXMT）的 LPDDR 产品为例，看一个「模拟/存储为主」的产品是如何与我们的知识框架对应的。

LPDDR 是什么：Low Power Double Data Rate SDRAM，面向移动设备（手机/平板）的低功耗 DRAM 内存。代际：LPDDR4 → 4X → 5 → 5X → 6。

LPDDR = Low Power + Double Data Rate + SDRAM
       = 省电版 DDR 内存（给手机当"运存"）

内部构成（关键） ：DRAM 芯片不只是"存储阵列"，它同时含数字与模拟电路。

┌───────────── LPDDR 芯片内部 ─────────────┐
│  存储阵列（模拟味重）                      │
│  ├─ 电容式 bitcell（存电荷 = 模拟量）      │
│  └─ 灵敏放大器 / 电荷泵 / 参考电压          │
│                                          │
│  数字控制逻辑（★ 走我们的 RTL→P&R 流程）    │
│  ├─ 命令译码 / 时序控制                    │
│  ├─ 刷新控制 / 模式寄存器                   │
│  ├─ 地址缓冲 / 数据通路                    │
│  └─ 测试与自校准（BIST 等）                 │
│                                          │
│  接口 PHY（模拟/混合）                     │
│  └─ 高速驱动、接收、阻抗匹配、DLL           │
└──────────────────────────────────────────┘
指标 DRAM / LPDDR CPU / GPU
数字电路占比 小 大（~99%）
需要 P&R 吗 需要（但范围小） 核心环节
P&R 难度 相对低（数字块小、规整） 极高（上亿门、复杂约束）
产品难点在 存储阵列 + 模拟 P&R + 时序收敛

结论：DRAM / LPDDR 的数字部分确实也走我们的 RTL→综合→P&R 流程，但因为占比小、瓶颈不在这，所以它不是研究 P&R 的典型对象。不是"不需要"，而是"够用就行"。真正研究 P&R 的战场是 CPU / GPU / SoC 这类数字密集型芯片。

各产品与 RTL→P&R 流程的关系#

产品 走 RTL→P&R 吗 P&R 地位
CPU / GPU ✅ 全面走 核心，最难
SoC（手机芯片） ✅ 数字部分全面走 核心
SRAM 缓存 ✅ 周边逻辑走，阵列手工 中等
DRAM / LPDDR ✅ 部分走（控制逻辑） 次要
Flash / NAND ✅ 部分走 次要
ADC / 射频 / 电源 ❌ 基本不走 无

一句话：产品 = 数字 + 模拟 + 存储宏的组合；数字占比小的产品（如 DRAM）也走我们的流程，但那不是它的主战场。我们学 P&R，重点是数字密集型芯片。

3. 前端设计：想法 → 逻辑网表#

① RTL 设计#

  • RTL = Register Transfer Level（寄存器传输级）
  • 用 Verilog / VHDL / SystemVerilog 描述电路行为，不关心用几个门、怎么连
  • 分可综合、不可综合；可仿真验证
always @(posedge clk) begin
    if (en)
        q <= d + 1;   // 描述"加法 + 时序"这一行为
end

类比：写软件的"源代码"，能跑、能验，但还没变成机器指令。

② 功能验证#

  • 跑仿真、写测试，确认逻辑正确
  • 耗时往往超过写代码本身
  • （待深入：验证方法学、UVM 等）

③ 逻辑综合（Synthesis）#

把 RTL 翻译 + 优化成真实逻辑门，做三件事：

步骤 内容
翻译 Translation d+1 → 一整套加法器逻辑门
优化 Optimization 化简逻辑、合并同类项，用最少门实现
映射 Mapping 映射到具体工艺库的真实单元（带真实延迟/面积/功耗）
  • 输入：RTL 代码 + 约束（时钟频率/面积/功耗）+ 工艺库
  • 输出： 门级网表 + 时序/面积/功耗初步估算
  • 工具：Synopsys Design Compiler、Cadence Genus

类比：把 Python 源代码编译成机器码，顺便做编译器优化。

门级网表（Gate-level Netlist）#

综合的产物，描述两件事：

AND2X1  U1 (.A(a),  .B(b),    .Y(n1));
DFF_X2  U2 (.D(n1), .CK(clk), .Q(q));
INV_X1  U3 (.A(q),  .Y(out));
  1. 用哪些零件（Instances） ：具体标准单元
  2. 零件怎么连（Nets） ：引脚间连线关系

关键点：

  • 只有"门"和"线"， 没有行为了
  • 每个单元带真实物理参数 → 可做时序分析
  • 但还没有实际位置和尺寸，只是逻辑连接关系

类比：一份 BOM 清单 + 接线图，告诉你用哪些芯片、怎么连，但还没画 PCB 版图。

4. 后端设计：网表 → 物理版图#

④ 布局规划（Floorplanning）—— 打地基#

  • 定芯片尺寸（Die 面积）
  • 预留电源网格、 时钟网络
  • 摆放大块头：内存（SRAM）、IP 核、模拟模块（Macro）
  • 剩余空地留给标准单元

类比：装修先定冰箱、沙发等大件位置，再摆小物件。

⑤ 布局（Placement）—— 给标准单元找位置#

详见第 5 节。

⑥ 时钟树综合（CTS）#

  • 时钟要被同时送到所有触发器；走线延迟不同会导致到达时间不一致（ 时钟偏斜 Skew）
  • CTS 就是建一棵平衡的时钟分发树，把时钟均匀、同时送达
  • （待深入）

⑦ 布线（Routing）—— 把线真正连起来#

详见第 6 节。

⑧ 签核（Signoff）—— 全面体检#

检查：时序、功耗、DRC（设计规则）、IR Drop、EM、串扰等。 全部达标才算设计完成。

5. 深入一：布局 Placement#

5.1 概念#

布局 = 给芯片上每个标准单元找一个合法、不重叠、且"连线短、时序好、不拥塞、面积小"的位置。

5.2 摆放对象#

  • 标准单元（Standard Cell） ：综合出的与门/或门/触发器/缓冲器等
  • 特点： 等高矩形积木，排成一行一行（Row），宽度不等
  • 本质：给每个积木分配一个行列位置
┌─────────────────────────────────┐
│  [宏单元 SRAM]        [IP核]     │
│                                 │
│  ┌───────────────────────────┐  │
│  │ ▭ ▭ ▭ ▭  ▭ ▭  ▭ ▭ ▭ ▭ ▭ │  ← 一行标准单元
│  │ ▭ ▭  ▭ ▭ ▭ ▭ ▭  ▭ ▭ ▭ ▭ │  ← 一行标准单元
│  │ ▭ ▭ ▭ ▭ ▭ ▭  ▭ ▭ ▭ ▭ ▭  │  ← 一行标准单元
│  └───────────────────────────┘  │
└─────────────────────────────────┘

5.3 优化目标（互相冲突）#

目标 通俗解释
线长最短 有连线关系的零件尽量摆近（常用 HPWL 估算）
时序达标 关键路径零件挨近，信号跑得快
避免拥塞 别堆太挤，否则后面布线布不下
面积小 面积直接决定成本
功耗低 线短、开关少 → 省电

核心矛盾：

  • 摆密 → 线短但拥塞
  • 摆散 → 通畅但线长、时序崩

5.4 两步走#

  1. 全局布局（Global Placement） ：粗摆，确定大致位置， 允许重叠，压线长、摊平热点
  2. 详细布局 + 合法化（Detailed Placement / Legalization） ：精修，消除重叠，对齐合法行与网格
粗摆（有重叠）          合法化后（整齐无重叠）
▭▭▭▭▭ ▭▭              ▭ ▭ ▭ ▭ ▭ ▭ ▭
 ▭▭▭▭▭▭▭       →      ▭ ▭ ▭ ▭ ▭ ▭ ▭
  ▭▭▭▭▭▭              ▭ ▭ ▭ ▭ ▭ ▭ ▭

5.5 难点#

  • 规模巨大（百万~千万单元，组合数天文）
  • NP 难，多目标优化，只能逼近最优
  • 必须替布线"操心" （预判可布线性），否则布线阶段直接崩
  • HPWL 只是直线距离近似，无法反映真实走线——这是"布局布线分离"的根本痛点

5.6 经典算法（待深入）#

  • 二次规划 + 解析法（ePlace、RePlAce、DREAMPlace/GPU 加速）
  • 模拟退火（TimberWolf）、力导向、分区法

6. 深入二：布线 Routing#

6.1 概念#

布线 = 照网表，用多层金属把引脚连起来，且要连得下、连得对、不违规。

6.2 物理背景：金属层#

M8 ──────────────────   高层：线宽大、电阻小 → 关键信号
M7    (垂直走线)
M6 ──────────────────
M5    (垂直走线)
M4 ──────────────────
M3    (水平走线)
M2   ▭ ▭ ▭  ← 标准单元引脚
M1
  • 相邻层方向相反（横一层、竖一层），用过孔（Via） 换层
  • 每条线只能走在固定轨道（Track） 上

类比：城市交通，有高架、有地面道路；竖路和横路交叉要上下桥（过孔）换道。

6.3 三步走#

  1. 全局布线（Global Routing） ：切成 G-cell 网格，定每条线走哪些格子/哪层，不指定具体轨道
  2. 轨道分配（Track Assignment） ：把大致路径落到具体轨道
  3. 详细布线（Detailed Routing） ：确定每条线、每个过孔的确切位置，满足所有制造规则

6.4 硬约束#

约束 通俗解释
设计规则 DRC 最小线宽/间距/面积，违反=废片
容量 通道线数有限，超了 → 拥塞
时序 关键路径走宽线、走捷径
串扰 线挨太近会互相干扰
天线/EM 等 先进工艺附加规则

6.5 难点#

  • 拥塞（Congestion） ：最大敌人，常需回头改布局
  • NP 难 + 规模爆炸（网格数可达 10⁹ 级）
  • 多约束（DRC/时序/串扰/功耗）同时满足
  • Rip-up and Reroute：拆线重布，现代布线器核心手段

7. 贯穿始终的两条主线#

主线一：时序（Timing）#

芯片能跑多快 = 信号能否在一个时钟周期内到达。每个阶段都要看时序报告，不达标就回退改。

主线二：迭代（Iteration）#

设计是"不断打回重做"的过程，不是流水线走一遍就完事。

   验证 ←──────┐
      ↓        │
   综合 ←───┐  │
      ↓     │  │
   布局 ←─┐│  │    ← 任何一步发现问题都可能回退
      ↓  ││  │
   布线 ←┘┘  │
      ↓     │
